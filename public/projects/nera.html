原始問題

Agent 可以很快寫出一套看似完整的分析腳本與報告，但常常在三個地方失真：忘記原始研究目標與停止條件、在跨 Session 交接時把假設當成已驗證結論，或是為了「做出顯著結果」而無意間滑向切點挑選（P-hacking）。

治理與驗證做法

以中心 Goal 為起點，允許有界拆解，但每個子任務都必須回到父目標驗收。審查意見、Lead 裁決、官方資料來源收據（source receipt）與人類授權明確分離；生醫分析端則同時用 Python 與 R（cox.zph 等假設檢定）做交叉核對。

實際進展與互動展示

在 TCGA-KIRC 524 位腎細胞癌公開臨床資料上，我們完成了官方來源稽核、分層存活分析與 CP04 v2 交叉驗證，並把結果做成純靜態預計算的互動工具——你可以直接在 TCGA-KIRC 存活敏感度實驗室 拖動年齡切點，親眼觀察單一指標如何因為切點挑選產生假象，並查看 CP04 v2 交叉驗證的陰性結論。

在治理測試端，也透過破壞／變異測試（刻意移除部分規則檢查）發現某些規則在移除後仍未被既有測試擋下，將這些缺口保留為後續修正線索，而非包裝成 100% 通過率。

能力邊界與限制

本專案的互動展示與分析僅供統計方法教學、資料查核與作品展示，不構成臨床建議，亦未宣稱已通過正式醫學同儕審查。既有雲端協作流程仍依賴人工把關關鍵 Gate，無法取代合格領域專家的科學審查。
