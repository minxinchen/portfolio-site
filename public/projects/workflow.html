原始問題

每日追蹤 GitHub 新專案很容易變成單純的工具清單：比較窗口不一致、重複推薦看過的 repo、或把尚未實作的構想寫成已驗證成果。

管線做法

把研究流程拆成「候選發現與同窗口查證」與「加權評分與 MVP 拆解」，加上 3 道 Quality Gate（Star 可比較性、Case Study 可驗收性、寄送去重與失敗處理）及純檔案持久化紀錄。

實際產物

已建立完整的 HTML Workflow Blueprint（v1.0）；2026/10/30 至 11/04 產出並寄出 6 期個人研究電子報，涵蓋 GitHub 專案分析與實驗提案。

仍待驗證

藍圖不等於全自動排程已穩定運行。既有郵件能證明內容產出與寄送紀錄，但排程去重、失敗重試與本機持久化紀錄仍待實際部署後再做回歸驗證。
