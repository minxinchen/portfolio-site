AGENT / NIO'S JOURNAL

換了一個 Session，決策還留得住嗎？

從對話交接失真，談專案狀態、權威來源與執行環境的角色。

Nio Chen研究筆記 · 草稿繁體中文

在雲端對話中推進長期專案，有時候最困難的不是回答問題，而是下一段對話能不能正確接住上一段的決策。

為什麼一份 Handoff 還是不夠？

交接文件能幫助新的 Agent 快速理解背景，但它本質上是對歷史狀態的摘要。摘要可能遺漏限制、混淆已完成與待驗證的工作，也可能把上一輪的推測誤認成已授權的決定。

跨對話記憶能減少這些問題，卻不能保證每次取回的都是正確版本，更不能替代實際測試。

交接摘要提供理解；權威狀態與驗收紀錄，應該另外保存。

把推理與執行環境分開

對 NERA 而言，一個值得探索的方向，不是把大型模型下載到本機，而是將專案的規則、版本、原始資料、測試與執行工具置於可持續存取的工作環境。Agent 仍然可以使用雲端 SaaS 模型，但新 Session 應讀取同一套專案事實。

這並不會自動解決所有問題。規則檢查器本身仍可能有缺漏，Reviewer 也未必真正獨立。相較於只靠自然語言報告，它至少使部分問題具備可重跑與可核對的條件。

驗證需要驗證自己

一組測試全部通過，並不代表規則不會被繞過。刻意修改比較運算、邏輯關係或移除規則檢查，再觀察測試是否能辨識破壞，是一種重新檢查測試有效性的方式。

近期 NERA 的破壞測試摘要揭露過規則移除仍可能未被測試擋下的情況。這應被視為後續改善的線索，而不是另一個值得包裝成績效數字的指標。

本文狀態

這是一篇基於實際討論與專案紀錄整理的研究筆記，並非已完成的跨平台實驗報告。NERA 搬遷本機後的驗證結果尚未在本文宣稱完成。

下一個合理的問題

如果讓不同 Agent 在新的 Session 中讀取同一版本的 Goal 與 State，它們能否更準確地延續工作？這比比較哪個模型寫得更流暢，可能更接近問題核心。

研究筆記可能隨新證據更新，實驗設計與實際驗證結果會分開標示。
