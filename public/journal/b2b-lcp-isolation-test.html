驗證與實測 // B2B SEO & PERFORMANCE

只動首屏就把 Mobile LCP 從 13.1s 壓到 2.7s：多語系統隔離測試筆記

處理一套 B2B 工業設備多語系統時，手機首頁載入卡在 13.10 秒。沒有先換主機或裝一堆外掛，先只替換首屏做隔離測試，數字直接掉到 3.16 秒。

一開始列出的嫌疑清單有主機回應、首頁 Slider、圖片體積、JavaScript 與快取。如果一次全改，成本高又找不到真正的元兇。我先開一個只動首屏的對照測試，確認光是拿掉沉重的首屏載入就把 LCP 壓掉將近 10 秒，才正式動網站上線，最終落點約 2.72 秒。

順手整理的三個 B2B 內容查核坑

整理多語系統規格表、產品頁與競品比較時，AI 幫忙產稿速度很快，但也最容易在三個地方露餡：

  • 只讀官網規格會失真：官網型錄每家都寫得完美，把官方文件跟論壇、經銷商、二手機市場的實際停機與服務回饋放在一起對照，才看得出承諾跟現場的落差。
  • 存在不等於會用：看過最離譜的自動推論是「客戶廠房裡已經有某牌控制器，所以操作員不用重新學習」。就像電腦裝了 Python 不代表人是工程師，跨層跳躍只要出現一次，內行人就不會信整頁內容。
  • 還沒自動化的步驟要直接講清楚：哪一段已上線、哪一段目前仍是人工串接，直接寫在流程裡比硬包成漂亮術語更耐得住追問。

這套從真實多語系統踩出來的查核習慣，後來也直接帶進了 WP Search Lab，以及後續的 GSC 未索引拆解指南。
