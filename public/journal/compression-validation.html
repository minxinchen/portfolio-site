驗證與實測 // 2026-05

n=10 跑出 100% Pass 卻讓我起疑：論文壓縮實驗的四個盲點

拿 10 篇腸腦軸 PMC Open Access 論文測雙 Reviewer 壓縮流程（目標保留 65% ± 3% 字元），v1 跑出 100% pass、平均 1.3 輪。數字很漂亮，但回頭拆變因後發現這輪其實什麼都還沒證明。

Nio Chen 分類：驗證與實測 Repo：document-compression-lab ↗

v1 的做法是讓一個 Writer 壓縮論文，再交給 Haiku（查格式與字數）跟 Sonnet（查語意與數據保真）輪流審。10 篇全過之後，我反問了一個問題：如果今天要把這套流程長期拿來訓練 Agent，這組 100% 能不能拿來當證據？答案是不行。

四個實際抓出來的盲點

盲點 v1 發生了什麼事 v2 改法
1. 指標飽和 保留 65% 時通過率已經頂到 100%，分不出 Prompt 或架構差異。 改看還有空間的指標（平均迭代次數、修訂數、字數變異），並規劃壓到 50%/40%/30% 測斷裂點。
2. 變因混在一起 模型隨機性、論文難度、Prompt、雙 Reviewer 全部混在單次 n=10 裡。 把 v1 歸檔到 agents_archive/compressor.v1.md 當對照組；每條防呆規則標上失敗來源（如 [src: lab/01/iter2/H4]），方便做消融對照。
3. 均勻砍字傷到數據 「邊寫邊算字數」讓模型在最後為了湊 65%，直接砍掉 Results 裡的對照數字。 拆成 Plan → Execute → Audit → Emit，先分配非均勻章節預算（優先保 Results，多削 Intro/Methods）。
4. 中文評估詞雙向歧義 同期審查表用了「踩了／沒踩」，結果有人讀成「踩中達標」，有人讀成「踩雷違反」。 給 Agent 和 Evaluator 讀的規則與標籤全面改英文（或明確定義「合規／漂移」），交付給人看才翻中文。

v2 刻意拒絕的兩個功能

升級 v2 時，我們排除了兩個看起來很合理、但會毀掉觀測準度的設計：

  • 不把「壓縮理由（rationale）」送給 Reviewer：Writer 如果附上一整段解釋「我為什麼刪這句」，Reviewer 很容易被說服，失去雙盲獨立判斷。
  • 不做語意 Self-Review：Stage 3 Audit 只檢查字元數、括號等機械條件。如果 Writer 自己先修掉語意缺陷，Reviewer 抓到的 issue 數下降時，會分不清是規則變好還是缺陷被藏起來了。改由 Writer 在輸出時填寫 SELF_DOUBT，事後對照它自己沒把握的地方是不是真的被 Reviewer 挑中。
展開：目前進度與尚未跑完的項目

v1 歸檔、v2 四階段規格與回歸測試架構已整理在 document-compression-lab ↗。拿全新 10–30 篇 PMC 論文跑 v1 vs. v2 成對消融實驗尚未執行，目前先留作下一階段驗證。同一套「防假陽性」的檢查習慣，也可以在 TCGA-KIRC 存活敏感度實驗室 直接看到。
