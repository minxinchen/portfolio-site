ABOUT // NIO CHEN

關於我與這個網站

履歷表上已經有完整的工作年資與經歷，這個網站不重複貼履歷，而是把原本放在 GitHub 與本機實驗室的專案、工具和踩坑紀錄，做成打開網址就能直接閱讀與操作的技術部落格。

為什麼要自己維護這個站？

實務上，很少有人會一個一個點開 GitHub repository、翻完 README 再把程式跑起來。用靜態 HTML 整理成部落格和線上互動工具，閱讀門檻低很多，討論或交流時也能直接開畫面驗證，不用只靠口頭說明。

跨領域背景帶給我的習慣

我念的是生物資訊與醫學工程，後來走過研究資料整理、醫療器材臨床支援與 B2B 工業技術行銷。這些不同現場教會我同一件事：比起漂亮的名詞，更重要的是資料從哪裡來、假設在什麼條件下會失效，以及使用者在現場到底卡在哪一步。

我不是本科純軟體工程師，也不會把自己包裝成資深全端。我在專案裡的核心角色是需求拆解、開源工具選型、工作流程與驗收規則設計；程式碼實作與自動化測試則透過 AI 協作完成，並用真實公開資料與測試案例反覆檢查誤判。

本站的書寫原則

  • 區分事實、實驗與構想：已上線的功能、單次實驗結果與尚未部署的 Workflow 藍圖會明確分開標示，不把未來式寫成現在式。
  • 誠實保留限制與陰性結果：例如 TCGA-KIRC 交叉驗證的陰性結論、工具無法繞過登入牆的限制、競品重疊之處，都會直接寫出來。
  • 清楚標註開源與 AI 貢獻：第三方開源元件保留原始授權與作者出處，不將開源或模型產出宣稱為個人原創。
